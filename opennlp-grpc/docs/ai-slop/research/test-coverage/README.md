# Test coverage

Analysis of `findings/` for the whole workbench and gateway, prompted by a run
of drift bugs (missing vector space route, "Failed to read message." on the
native gateway, catalog ids with a dot, DEADLINE_EXCEEDED on large inputs, the
50-result cap on sealed indexes).

## The shape of the problem

Every drift bug had the same anatomy: the front end, the gateway's JSON
mapping, the protos and the service validators are four hand-maintained copies
of one contract, and no test compares any two of them. The details
(`findings/drift-analysis.md`):

- FE types are 100% hand-written (`src/api.ts:23-136`); responses are read as
  `unknown` and re-parsed defensively. No codegen anywhere.
- The gateway uses the strict `JsonFormat.parser()` (`GrpcJsonApi.java:103`):
  a misspelled field or enum is a runtime 400, never a compile or test failure.
  69 proto enum literals in the FE are all correct today, enforced by nothing.
- `test/api.test.ts:47-62` mocks fetch with an echo and asserts the body equals
  the literal the test wrote three lines earlier. 20 of 21 FE route tests are
  this mock. `GrpcJsonSearchApiTest.java:112-116` hand-writes the same JSON as
  a Java text block; the two copies are never compared.
- 36 of 37 gateway routes have a JUnit test, but only 2 are reached by an
  integration test against a real server. Playwright never runs in CI
  (`playwright.config.ts` throws without `OPENNLP_E2E_BASE_URL`);
  `docker/test-image.sh` is never invoked and its largest payload is 44
  characters, which is why the native decode failure got through. The native
  image has no test at all.
- Models & data and Lifecycle have zero e2e and own 14 of the 15 routes with
  no FE test of any kind.

## Live bugs the audit found

1. **Ordinal sentiment labels render as raw scores.** The demo's `en-sentiment`
   model returns `1_star` to `5_stars`; `visualization-data.ts:162-174` only
   knows `positive`/`negative`/`neutral` and otherwise returns the score, so a
   one-star sentence shows as +0.84, strongly positive. Every fixture uses the
   three known labels. Decision: map ordinal label sets to signed polarity by
   rank (1 star = -1, 3 stars = 0, 5 stars = +1, scaled by confidence), show
   the raw label in the tooltip, and stop labelling the lane's number "cosine"
   (`document-heatmap-view.ts:104,128`). Pin the label set at the integration
   layer against the catalog model.
2. **The deadline fix is half applied.** Only `analyzeDocument` and
   `formatDocument` scale with input size (`GrpcAnalysisRpc.java:138,145`);
   `GrpcSearchRpc.indexDocuments:107` still uses the flat 30 s default and
   indexing a novel with embeddings costs at least as much as analyzing it.

## Decisions

The researcher's sequencing is adopted with one change of order: fix the two
live bugs first, since each is an hour of work with a red test.

1. P1-2 (S): a vitest that loads the shipped descriptor set
   (`META-INF/opennlp/descriptors/opennlp-grpc-v1.protobin`, already built and
   already loaded by the service) and checks every FE enum literal and every
   `api.ts` interface key against it. Lands in the existing CI gate.
2. P1-1 (M): request fixtures generated by the real FE builder functions,
   checked in, and fed through `GrpcJsonApi.handle` plus the static service
   validators in a gateway JUnit test. Fixtures live with the front end; the
   gateway test consumes the built resources it already bundles.
3. P1-4 (M): run the Playwright smoke suite inside `docker/test-image.sh`
   against the built image, with a novel-sized payload, and invoke that script
   from a CI job. Wall-clock cost is the owner's call; release-time at minimum.
4. P2: size ladder for the deadline logic including `index-documents`; e2e
   specs for Models & data and Lifecycle; the one untested gateway route
   (`model-bundles`) and the stream readers; widen the integration suite.
5. P3: generate TS request types from the descriptor set (supersedes P1-2),
   give `main.ts` a seam, and either make `opennlp.forkCount` real for this
   subtree or stop documenting it (`opennlp-grpc-webapp/README.md:17`; the
   shared surefire block hard-codes `forkCount 1`, root `pom.xml:448`).

`/api/v1/output-formats` and `/api/v1/format-document` have no browser caller;
they are kept as programmatic routes and the export-format picker in
`../roadmap` track 5 is what will use them.
